# AI MC 스튜디오 — 발전 방향

작성: 2026-10-28 · 상태: 제안, 아래 기능과 수락 기준은 아직 완료된 것으로 간주하지 않는다.

## 목표

**CJ와 게스트가 AI MC와 함께 30분짜리 한국어 팟캐스트를 반복해서 녹음하고, 편집 가능한 결과물을 얻는 스튜디오.**

현재 구현과 확인된 근거는 [STATUS.md](STATUS.md), 구조와 단계는 [PLAN.md](PLAN.md)에 기록한다. 현재 짧은 대화 표본만으로 기본 엔진이나 페르소나의 우열을 결정하지 않는다.

## 우선순위 1 — 실제 대화 품질을 비교할 기준 마련

같은 주제·같은 페르소나·같은 마이크 조건으로 GPT-Live와 Gemini Live를 각각 10분씩 3회 평가한다. 처음에는 페르소나 하나를 고정하고 엔진만 바꾼다. 엔진을 고른 뒤 페르소나를 비교하면 원인을 구분하기 쉽다.

평가 시나리오에는 다음을 포함한다.

- 자연스러운 스몰토크와 후속 질문
- CJ가 생각하며 잠깐 멈추는 상황
- MC가 말하는 중 CJ가 끼어드는 상황
- 정지·재개·넘기기·귓속말
- 명확히 최신 사실 확인을 요청하는 질문과 검색이 필요 없는 일상 질문
- 중간에 세션을 종료한 뒤 녹음·대화록·사용량을 확인하는 과정

### 제안하는 수락 기준

| 항목 | 기준 |
|---|---|
| 측정량 | 엔진당 10분 × 3회, 유효 응답 지연 표본 최소 30개 |
| 응답 지연 | 중앙값 ≤ 1.2초, p95 ≤ 2.0초 |
| 부적절한 끼어들기 | 10분당 0~1회; 사람의 의도적인 끼어들기와 별도로 기록 |
| AI 정지 | 실제 들리는 소리가 멈추기까지 ≤ 300ms |
| 한국어 자연스러움 | CJ 평가 4/5 이상 |
| 발화 습관 | 과잉 긍정·질문 되돌리기·긴 발화 횟수를 기록하고 회차별 비교 |
| 기록 완결성 | 모든 종료 세션에 음원·대화록·리포트 존재 |

수치는 목표이며 현재 달성 사실이 아니다. 지연은 모델이 보고한 수치뿐 아니라 실제 송출 시점으로 측정하고, 표본 수와 측정 방식도 함께 남긴다. 비용은 마지막 턴 누락 가능성을 표시한 추정치로 다룬다.

**첫 개발 묶음 제안:** 평가 시나리오와 회차별 평가 입력표, 수동 품질 점수·이벤트 마커, 엔진 비교 CSV 내보내기. 음성 프롬프트 변경 전후를 같은 시나리오로 비교한다.

## 우선순위 2 — 녹음 보존과 장시간 연결

`output`에는 종료 리포트가 없는 과거 세션도 있다. 원인은 아직 확인하지 않았으므로, 종료 중단과 장애 복구를 별도 시험한다.

- 세션 상태를 시작·진행·정상 종료·중단·복구로 구분하고 기록한다.
- 진행 중 오디오와 메타데이터를 주기적으로 저장하고, 앱 재시작 시 미완료 세션을 찾는다.
- 미완료 세션의 WAV 헤더·대화록·리포트를 복구하며 누락 구간을 명시한다. 원본 파일을 보존한다.
- Gemini의 세션 이어받기·컨텍스트 압축·연결 종료 예고 처리를 실제 장시간 대화로 확인한다.
- GPT-Live 연결 종료 시 사용자에게 명확히 알리고, 재시작 시 문맥을 전달할 범위를 정한다.
- 연결 상태와 재접속 사건을 화면·리포트에 남긴다.

**통과 기준:** 30분 연속 녹음, 이후 60분 녹음. 네트워크 단절·브라우저 재접속·서버 비정상 종료를 각각 재현하고, 저장된 오디오 보존·중복 인사 방지·누락 구간 표시·복구 결과를 확인한다. 정상 종료된 회차는 사람이 반복해서 열어 듣고 편집 도구로 가져올 수 있어야 한다.

## 우선순위 3 — 외부 게스트를 포함한 3인 파일럿

- 외부에서 접근 가능한 HTTPS 게스트 입장 페이지와 연결 상태 화면을 준비한다.
- 입장 전에 마이크 선택·입력 레벨·헤드셋·테스트 재생을 확인한다.
- 초대 링크 만료·취소·재사용 정책을 정하고, 게스트에게 녹음 여부를 표시한다.
- LiveKit 전체 재접속 후 트랙이 다시 게시돼도 사람 식별자와 녹음 파일이 올바르게 연결되는지 확인한다.
- CJ와 게스트끼리 대화할 때 MC가 기다리는지, 동시 발화 때 화자를 잘못 표시하지 않는지 평가한다.

**통과 기준:** CJ + 외부 게스트 + AI MC가 15분 대화. 세 사람의 트랙·믹스·대화록 시간축을 확인하고, 게스트 재접속 후 화자와 녹음이 유지되는지 검증한다. 이 단계가 끝난 뒤 30분 모의 회차로 늘린다.

## 우선순위 4 — 편집용 녹음 품질

현재 녹음은 **서버가 LiveKit에서 받은 24kHz 모노 PCM**과 MC 송출 음성을 저장한다. 브라우저에서 네트워크 전송 전에 확보한 원음은 아니다.

먼저 현재 녹음의 끊김·시간축·클리핑·복구를 확인한다. 네트워크 손실이나 음질이 실제 편집에 문제가 되면 브라우저 로컬 녹음을 추가한다.

- 브라우저 녹음을 작은 조각으로 저장하고 업로드를 재개할 수 있게 한다.
- 전송 전 녹음과 서버 녹음을 공통 시간축에 맞추고, 검증 가능한 동기화 표식을 둔다.
- LiveKit Egress는 서버 측 백업 후보로 평가한다. 서버 수신 트랙 녹음을 브라우저 원음으로 표시하지 않는다.
- 회차 내보내기에 음원 목록·샘플레이트·동기화 기준·누락 여부를 포함한다.

## 우선순위 5 — 반복 제작과 영상 확장

30분 파일럿을 2회 이상 안정적으로 마친 뒤 다음 순서로 확장한다.

1. 진행표·코너 타이머·코너 전환 지시
2. 수동 하이라이트·챕터·SRT 자막 내보내기
3. 편집용 묶음 내보내기와 회차 보관 정책
4. 오디오에 반응하는 캐릭터와 짧은 영상 클립

장기기억, 자동 게스트 조사, 영상 편집 UI는 실제 제작에서 필요한 지점이 드러난 뒤 우선순위를 정한다. 다음 개발의 핵심 산출물은 새 화면 수가 아니라 **완결된 파일럿 회차와 품질 비교 결과**다.
