# AI MC 팟캐스트 — 음성 우선 재개발 계획 (v2)

작성 2026-10-24 · 상태 갱신 2026-10-28

v2는 Discord 대신 전용 웹 + LiveKit을 사용하며, OpenAI GPT-Live와 Gemini Live를 선택할 수 있다. 현재 증거와 검증 한계는 [STATUS.md](STATUS.md), 다음 실행 순서는 [ROADMAP.md](ROADMAP.md)에 기록한다.

## 1. 목표

**1순위:** AI MC가 음성방에 실제로 들어와 CJ(이후 게스트 포함)와 팟캐스트처럼 자연스럽게 대화한다. CJ는 웹 화면에서 MC를 설정하고(OpenAI Playground의 Live 설정 창과 같은 구성) 방송 중에 제어한다.

| 지표 | 1차 목표 |
|---|---|
| 사람 발화 종료 → AI 첫 소리 | 중앙값 ≤ 1.2초, p95 ≤ 2.0초 (화면 "응답 지연"으로 측정) |
| AI 정지 버튼 → 소리 멈춤 | ≤ 300ms (로컬 재생 큐 폐기 기준) |
| AI가 사람 말을 자른 횟수 | 10분당 0~1회 |
| 한국어 자연스러움 | CJ 평가 4/5 이상 |

범위 밖 (음성 대화가 기준을 통과한 뒤 진행): 영상·캐릭터, 장기기억 DB, 게스트 자동 조사, 편집 UI.

## 2. 왜 Discord가 아니라 전용 웹인가

- Discord 수신·암호화 연동을 별도로 운영하는 부담을 줄이고, 웹에서 참가자별 음성·설정·제어를 한곳에 모으기 위해 LiveKit을 선택했다.
- 현재는 서버에서 참가자별 수신 PCM을 녹음한다. 각 브라우저가 원음을 따로 녹음해 업로드하는 경로는 후속 작업이다.
- 게스트 페이지는 링크 클릭 → 마이크 허용으로 입장하는 구조다. 공개 페이지 배포와 외부 게스트 접속은 실제 시험이 필요하다.
- 지연과 끼어들기 품질은 엔진·네트워크·마이크 조건에 따라 달라지므로 실제 세션으로 측정한다.

## 3. 구조

```
[CJ 브라우저: 스튜디오 화면] ─┐                      ┌─ [게스트 브라우저: /join 링크]
                              └── LiveKit (WebRTC) ──┘
                                        │
                          [AI MC 에이전트 · CJ PC의 Node 서버]
                           사람별 음성 수신 → 화자 감지(VAD)
                           → 믹싱·엔진별 오디오 변환
                           → GPT-Live 또는 Gemini Live (WebSocket)
                           ← MC 음성 → 재생 큐 → LiveKit 송출
                           수신 사람 PCM + 실제 송출 MC PCM → 분리 WAV·리포트
```

- **스튜디오 서버** (`server/`): 127.0.0.1 전용. 설정 저장, LiveKit 토큰·초대 링크 발급, 에이전트 실행, 로그 방송(WebSocket).
- **에이전트** (`server/agent/`): LiveKit 방 참가자 "AI MC". 사람 음성을 섞어 선택한 엔진으로 보내고, MC 음성을 방에 내보낸다.
- **웹** (`web/`): 스튜디오 화면(설정 패널, 대화 로그, 제어 버튼, 참가자 레벨)과 게스트 입장 페이지.
- **녹음** (`server/recording/`): 서버가 받은 사람 PCM과 실제 송출 MC PCM을 같은 시간축에 기록한다. 종료 시 믹스·대화록·리포트를 만든다. 브라우저 원음 녹음·업로드는 포함하지 않는다.
- **공통 설정** (`shared/`): 엔진별 설정, 페르소나 트랙, 직접 작성 프롬프트, 오프닝 방식, 진행 규칙을 관리한다.

### GPT-Live 어댑터의 현재 제어 방식

현재 어댑터는 모델의 자율 발화를 사용하고, `response.cancel` 대신 아래 지시와 로컬 송출 제어를 사용한다.

- `session.instructions.append`: 지시 (말하는 중에도 끼어들 수 있음)
- `session.thinking.append`: 말하지 않고 맥락만 추가 (예: "지금 말하는 사람: 게스트")
- `session.commentary.append`: 말할 내용 요청 (의역될 수 있음)
- 로컬 재생 큐 폐기 (정지 버튼)

에이전트가 사람별 VAD로 화자를 판정해서 진행 메모로 알려주고, 로그의 전사에도 이름을 붙인다. 겹말의 화자 정확도는 실제 3인 대화로 확인해야 한다.

모델·음성·프롬프트는 세션을 다시 시작해 적용한다. 백엔드 설정 갱신과 앱의 발화 감지 설정은 별도 경로다.

### Gemini Live 어댑터의 현재 제어 방식

2026-10-25 추가했다. 모델·음성·생각 깊이·Google 검색 설정을 제공한다. `interrupted` 이벤트를 받으면 재생 대기 음성을 비우며, 대화 기록 압축과 세션 이어받기 핸들을 사용하는 재연결 코드가 있다. 모의 프로토콜 시험과 실제 장시간 연결 복구는 구별한다. 2026-10-26의 짧은 사람 대화는 `gemini-3.8-live-extended-thinking` 설정으로 기록됐다.

프롬프트 본문과 페르소나 운영 규칙은 두 엔진이 공유하고, 검색 방식만 엔진 부록으로 붙인다 (`shared/settings.ts`의 `ENGINE_APPENDIX`). 검색은 명시적으로 요청할 때 사용하도록 지시한다. 세션 종료 산출물은 `output/<세션>/`, 엔진 비교용 요약은 `data/sessions/<id>/summary.json`에 저장한다. 화면 비용은 코드의 요금 가정에 따른 추정치이며 실제 청구액 검증은 아니다.

추가 엔진은 실제 3인 시험에서 제어·음성 품질의 문제가 확인된 뒤 결정한다. 응답 시점을 앱이 직접 제어하는 Realtime 방식이나 STT → LLM → TTS 방식을 검토할 수 있다. 새 엔진은 `server/engines/`의 공통 어댑터 형태로 추가한다.

## 4. 단계

| 단계 | 내용 | 상태 | 통과 기준 |
|---|---|---|---|
| **P0** | 스튜디오·게스트 페이지·두 엔진·페르소나·진행 제어 | 구현됨. 자동 테스트 29/29, 타입 검사 통과 | 단위·프로토콜 검사와 실제 사용 흐름 확인 |
| **P1** | 실제 연결 시험: CJ 혼자 + AI MC | 진행 중. Gemini로 43초 사람 대화 확인 | 10분 대화, 지연·자연스러움·정지 지연 측정 |
| **P2** | CJ + 테스트 게스트 + AI 3인 대화 | 미검증. 저장된 게스트 트랙 없음 | 15분, 잘못된 끼어들기 0~1회, 겹말·화자·재접속 확인 |
| **P3a** | 서버 수신 사람 PCM·실제 송출 AI PCM 녹음, 믹스·리포트 | 구현됨. 짧은 CJ/MC 분리 WAV 확인 | 실제 3인 세션에서 트랙 누락·정렬·종료·복구 검증 |
| **P3b** | 각 브라우저 원음 녹음·업로드 | 미구현 | 원음 파일과 서버 트랙의 정렬, 업로드 재시도·복구 검증 |
| **P4** | 진행표·진행 기술·공개 게스트 페이지 | 후속 단계 | 외부 게스트 접속과 30분 모의 회차 |

P1은 실제 연결 후 장시간 수락시험을 진행하는 단계다. 저장된 지연 표본 두 건으로 목표 충족을 확정하지 않는다. P3a의 WAV는 서버 수신 음성이므로 P3b의 브라우저 원음 확보 완료로 간주하지 않는다.

## 5. 위험

| 위험 | 대응 |
|---|---|
| GPT-Live가 CJ·게스트끼리의 대화에 끼어듦 | 프롬프트 규칙 + 화자 메모 + 정지 버튼. 안 되면 Realtime 엔진 (앱이 응답 시점 결정) |
| 정지 후에도 모델이 계속 말하려 함 | 재생 큐를 폐기하고 HOLD 동안 출력 음성을 버림. 재개 전까지 송출 없음 |
| 모델 출력이 실시간보다 빠르게 몰려옴 | 재생 큐로 받아 20ms 단위로 송출. 정지 시 큐 전체 폐기 |
| 백엔드 모델 이름이 계정마다 다름 | 설정 창에서 직접 입력. 계정의 `/v1/models` 목록을 제안으로 표시 |
| 에코 | 브라우저 에코 제거 + 헤드셋 안내 |
| 수신 전 네트워크 손실로 사람 음성이 빠짐 | 서버 수신 녹음의 한계로 기록. 브라우저 원음 녹음·업로드는 P3b에서 검증 |
| 비정상 종료 뒤 리포트가 남지 않음 | 종료·재시작·중간 산출물 복구를 녹음 수락시험에 포함 |

외부 서비스의 현재 모델 제공 여부·한도·요금은 실제 계정으로 시험할 때 확인한다. 이 문서의 구현 상태와 과거 세션 기록은 공급자의 최신 사양을 보장하지 않는다.
